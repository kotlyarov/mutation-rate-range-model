# Data Plan

This document describes how empirical data should eventually be used in the Mutation Rate Range Model.

## Current status

The repository includes a small source registry, schema example, and an early
processed Sprouffske et al. 2018 calibration dataset. These are data curation
inputs, not validated fitted model parameters.

The current lineage model should not pretend that parameters are fitted to data
until source validation, fitting, and uncertainty treatment are complete.

Current scaffolded files include `data/source_registry.json`, raw Sprouffske
2018 files under `data/raw/sprouffske_2018/`, and early processed CSV files
under `data/processed/`. The Streamlit app does not currently consume these
files during a lineage run.

## Data goals

The eventual goal is to compare model behaviour against empirical patterns such as:

- selected-environment fitness gain over generations
- mutation accumulation over generations
- mutation-rate differences between lineages
- robustness or performance in alternative environments
- evidence of genome decay or functional loss

## Candidate data sources

Potential sources include:

- LTEE fitness data
- LTEE mutation datasets
- LTEE Mutation Finder
- Couce et al. 2017 supplementary data
- Sprouffske et al. 2018 data and supplementary material
- published genome-sequencing datasets from LTEE-related studies

## Data directory policy

Use this structure:

```text
data/
  raw/
  processed/
  external/
  README.md
```

### `data/raw/`

Original downloaded files.

Do not manually edit files in this directory.

### `data/processed/`

Cleaned files generated by scripts.

Every processed file should be reproducible from raw data.

### `data/external/`

Small external reference tables or metadata files.

## Metadata requirements

For every dataset, record:

```text
source_name
source_url
access_date
license_or_terms
download_method
raw_filename
processing_script
notes
```

## Preprocessing rules

Preprocessing should be scripted.

Do not manually edit CSV files in spreadsheet software unless the change is documented and reproducible.

## First data milestone

The first data milestone should be modest:

```text
Collect one fitness-time dataset and one mutation-accumulation dataset.
Create a notebook that plots both without fitting the model.
Document caveats.
```

Do not fit model parameters until basic plotting and source validation are complete.

## Data validation checks

For each dataset:

- confirm expected columns exist
- check missing values
- check generation counts
- check lineage identifiers
- check units
- check duplicate records
- check that derived values are reproducible

## Fitting caution

Real-data fitting should be added only after:

- the current lineage model functions are tested
- core model functions are tested
- source data is documented
- validation plan is written
- uncertainty treatment is defined

## Reporting caution

Do not report fitted parameters without:

- source data citation
- fitting method
- uncertainty range
- sensitivity analysis
- limitations
